- Autonomous gate runs and the terminal stop decision are now host-observable. Each gate execution emits `autonomous_gate_started`, `autonomous_gate_passed`, or `autonomous_gate_failed` custom messages (the failure text carries the command, attempt counter, and exit reason; the full output rides in `details`), and the end of an autonomous run emits `autonomous_stopped` with the reason — all quality gates passed, or the named limit that stopped the run (with usage numbers). Hosts that watch the session (t3) can now show why the agent kept going and why it stopped, and the gate events double as liveness activity so a multi-minute gate command no longer looks like a hung run. Autonomous continuation user messages now carry an `isAutonomousContinuation` marker so hosts can distinguish agent-initiated continuation prompts from user submissions and steers, which arrive as identical message lifecycle events.
